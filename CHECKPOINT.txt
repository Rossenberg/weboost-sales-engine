==================================================
ПРИНЯТЫЕ РЕШЕНИЯ
==================================================

- Без n8n / Make — всё делаем обычным кодом (Python)
- База данных: SQLite локально на этапе тестов (data/weboost.db).
  Позже, при выходе в прод — перенос на Supabase без переделки структуры.
- AI-модель: OpenAI gpt-6-luna (ключ в .env, уже сохранён и рабочий).
  Сравнили с gpt-6-sol на тестовом лиде — качество анализа практически
  одинаковое, а luna в ~20 раз дешевле ($0.10/$0.50 за 1M токенов против
  $2/$10 у sol). Для объёма 10 000 лидов (7000 email + 3000 LinkedIn):
  ~$6 на luna против ~$119 на sol. Если в будущем качество на реальных
  (не тестовых) сайтах покажется слабее — можно быстро вернуть sol,
  это одна строка в .env.
- Стиль писем: "AI честно признаётся, что письмо написал не человек,
  а AI-система, которая исследовала компанию" — согласовано с пользователем,
  промпт лежит в prompts/email_generation_prompt.txt
- Email-рассылка: Instantly.ai, но ТОЛЬКО план "Growth / Outreach only" ($47/мес) —
  чистая инфраструктура отправки (ящики, прогрев, деliverability), БЕЗ их
  встроенного "AI Sales Agent" ($94+/мес) — свою AI-логику (анализ/скоринг/письма)
  уже построили сами, дешевле и полностью под контролем. Их лидовая база
  (450М контактов) — потенциально полезна ПОЗЖЕ, если понадобится автопоиск
  новых компаний (не входит в MVP). АККАУНТ ЕЩЁ НЕ СОЗДАН — открытый пункт.
- LinkedIn: только вручную (AI готовит черновик сообщения + ссылку, отправляет
  сам пользователь) — автоматическая отправка НЕ делается принципиально
  (риск бана аккаунта LinkedIn за автоматизацию).
- Dashboard: пользователь хочет красивый дашборд (все данные: отправлено,
  follow-up, ответы и т.д.) — будет строиться ПОСЛЕ того как в базе появятся
  реальные данные (чтобы было что показывать).
- Тестовые данные: 8 выдуманных лидов (логистика/3PL, домены *.example.com)
  в data/test_leads.csv — специально не резолвятся, чтобы протестировать
  обработку ошибок сайта.

==================================================
ЧТО УЖЕ СДЕЛАНО И ПРОВЕРЕНО (работает end-to-end)
==================================================

1. Структура проекта создана, git-репозиторий инициализирован (без коммитов).

2. База данных (scripts/schema.sql, scripts/db.py, scripts/init_db.py)
   - Таблица leads со всеми полями из ТЗ
   - Таблица lead_events (лог всех действий: WEBSITE_FETCHED, AI_ANALYSIS_COMPLETED,
     EMAIL_GENERATED и т.д.)
   - Полная модель данных описана в docs/DATA_MODEL.md

3. Импорт лидов из CSV (scripts/import_leads.py)
   - Дедупликация по домену сайта и по email — ПРОВЕРЕНО (повторный импорт
     тех же 8 лидов корректно пропустил все 8 как дубликаты)
   - Команда: python scripts/import_leads.py <путь_к_csv>

4. Исследование сайта (scripts/fetch_website.py)
   - Забирает главную + about/services/contact/pricing страницы
   - Чистит HTML, обрезает текст (контроль стоимости AI-вызовов)
   - При недоступном сайте не роняет весь процесс — помечает research_status
     PARTIAL/FAILED и продолжает работу с тем, что есть (ПРОВЕРЕНО на тестовых
     доменах, которые не резолвятся)

5. AI-анализ компании (scripts/ai_analysis.py + prompts/company_research_prompt.txt)
   - Структурированный JSON: наблюдаемые факты ОТДЕЛЬНО от предположений
   - Модель честно понижает confidence, если данных о сайте мало (проверено:
     0.28 при недоступном сайте, без выдуманных фактов)
   - Команда: python scripts/ai_analysis.py --limit N

6. Скоринг лидов (scripts/scoring.py)
   - 0-100, конфигурируемые веса в scripts/config.py (SCORE_WEIGHTS)
   - Категории LOW/MEDIUM/GOOD/HIGH

7. Генерация писем (scripts/email_generation.py + prompts/email_generation_prompt.txt)
   - Письма в согласованном стиле ("я не человек"), 60-120 слов, без буллшита
   - Ничего не отправляется — только сохраняется в базу со статусом READY
   - Команда: python scripts/email_generation.py --limit N
   - Все 8 тестовых лидов прошли полный цикл: NEW -> RESEARCHED -> READY

8. Центральная конфигурация (scripts/config.py)
   - DRY_RUN=true, AUTO_SEND=false по умолчанию (ничего не улетит случайно)
   - Все настройки (таймауты follow-up, лимиты отправки, пороги скоринга)
     в одном месте, не разбросаны по коду

9. Секреты
   - OPENAI_API_KEY и OPENAI_MODEL сохранены в .env
   - .env добавлен в .gitignore — никогда не попадёт в git/наружу
